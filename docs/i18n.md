# Translating Plotboek Generator

The UI speaks Dutch and English. Dutch is the **neutral** language: every string lives in a Dutch
`Resources/*.resx`, and English in the `*.en.resx` next to it. The code itself stays Dutch.

## How it works

- **Typed resource classes.** Each neutral `.resx` gets a generated class with one property per key
  (see the `Resources` item group in the project files), so `@PaginaUi.ElevatorPitchLabel` in a view or
  `CoreTekst.FeedbackZonderTekst` in code fails the build when the key doesn't exist. The class reads
  `CultureInfo.CurrentUICulture`.
- **The language of a request** is set by request localization (`LocalizationSettings`): the switcher's
  cookie, then the browser's `Accept-Language`, then `Localization:DefaultCulture`. Only the language of
  the text changes; dates and numbers keep the process's format, so nothing a form posts parses
  differently.
- **The Word export** always uses `Localization:DefaultCulture`, whoever exports it (`CultuurScope`).
- **Scripts** read their texts from `window.pbTekst`, which `Pages/Shared/_ScriptTekst.cshtml` writes from
  `ScriptTekst.resx`. A page renders that partial in its `Scripts` section before its scripts.
- **Terminology** (`Terminologie`): a word a deployment configures under `Terminology:*` is used in every
  language; a word it leaves alone is the translated neutral word.
- **Data is not translated.** Event names, time slots, encounter types, quest locations and everything
  people type are stored as they were entered. The reference host seeds its example LARP in the
  deployment's default language.

| File | Holds |
|---|---|
| `PlotboekGenerator.core/Resources/CoreTekst.resx` | Domain messages (validation results), change-history texts of the events, value-object texts that end up in the export, enum names, terminology defaults |
| `PlotboekGenerator.infrastructure/Resources/InfraTekst.resx` | Messages of the services (concurrency, Google Drive, Gemini) and the export builder's own words |
| `PlotboekGenerator.WebApp/Resources/Ui.resx` | The layout, the login and logout pages, Home, Privacy, Error, words shared by every page |
| `PlotboekGenerator.WebApp/Resources/PlotboekUi.resx` | The plotboek page: selection, settings, attachments, the plot list, the modals |
| `PlotboekGenerator.WebApp/Resources/PaginaUi.resx` | One plot (pagina): the details form, icons, feedback |
| `PlotboekGenerator.WebApp/Resources/AdminUi.resx` | The admin page and its partials |
| `PlotboekGenerator.WebApp/Resources/ScriptTekst.resx` | Texts the scripts in `wwwroot/js` show |

## Adding a string

1. Add the key to the Dutch `.resx` and the English `.en.resx` (Visual Studio's resource editor, or by
   hand: a `<data name="Key" xml:space="preserve"><value>…</value></data>` element in each).
2. Use it: `@PaginaUi.Key` in a view, `PaginaUi.Key` in code.
3. `Resources_specs` checks that both files have the same keys, no empty values, and the same `{0}`
   placeholders.

## Conventions

- **Keys** say what the text is for, in PascalCase: `SaveButton`, `ElevatorPitchLabel`,
  `ElevatorPitchHelp`, `FeedbackZonderTekst`. Domain words keep the code's spelling (Pagina, Plotlijn,
  Bijlage, Starttijd); the rest may be English or Dutch, as long as it reads as a name.
- **One sentence per key**, whole. Never glue fragments together in code: word order differs between
  the languages. A value with something in it uses `{0}`, `{1}`:
  `string.Format(CultureInfo.CurrentCulture, PlotboekUi.PaginaVerplaatst, titel)`.
- **No markup in resources.** Keep the HTML in the view and put only text in the resource. Where a sentence
  must contain a link or emphasis, split it at the markup, or, as a last resort, end the key in `Html`,
  render it with `Html.Raw`, and HTML-encode every argument you format into it.
- **Plural**: two keys (`…One`, `…Many`) and pick in code; no `(s)`.
- **Dates and times**: a month or day name follows the reader's language, so format it with
  `CultureInfo.CurrentUICulture` (`date.ToString("d MMMM yyyy", CultureInfo.CurrentUICulture)`); numeric
  formats and parsing stay invariant, as they are now.
- **Enum names** the reader sees come from `CoreTekst` (`Dag_Maandag`, `LocatieEncounter_Hoofdveld`, …),
  never from `ToString()`. The stored names don't change.
- **Logs stay English** and are not translated.
- **English** is British-neutral and plain: sentence case ("Save plot", not "Save Plot"), short, no
  exclamation marks, "sign in" (not "log in") for the action.
